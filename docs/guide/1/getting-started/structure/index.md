# Directory Structure

## The Root Directory

### The GitHub Directory

The `.github/` directory contains all is a special, hidden folder located in the root of a GitHub repository. It acts as the central control center for repository configuration, automation, and community health files.

- **`ISSUE_TEMPLATE/`**: Contains YAML files to create standardized forms for bug reports or feature requests. This ensures contributors provide all necessary details.
- **`workflows/`**: This folder contains YAML files that define your CI/CD pipelines. GitHub automatically runs these scripts based on triggers like pushes or pull requests.
- **`CODE_OF_CONDUCT.md`**: Sets the rules for community behavior.
- **`CONTRIBUTING.md`**: Guidelines explaining how developers can contribute to your project (e.g., local setup, coding standards).
- **`dependabot.yml`**: A configuration file used by Dependabot, a tool built into GitHub that automatically keeps your project's dependencies secure and up to date.
- **`PULL_REQUEST_TEMPLATE.md`**: A template that automatically populates the description field when someone creates a new Pull Request (PR), guiding them on what context to include.
- **`SECURITY.md`**: Instructions on how to responsibly and privately report security vulnerabilities.

### The PHPUnit Cache Directory

The `.phpunit.cache/` directory is a hidden cache directory used for the PHPUnit tests. This directory is ignored from commits.

### The Art Directory

The `art/` directory contains all files for the artwork. Inside of this directory you will find the `symfoniq.gvdesign` Gravit Designer working file.

### The Assets Directory

The `assets/` directory contains all public web assets, e.g. CSS, JavaScript, and image files that make the frontend of your site look and work great.

### The Binary Directory

The `bin/` directory contain all binaray files that can be used to execute commands.

### The Configuration Directory 

Symfony applications are configured with the files stored in the `config/` directory, which has this default structure:

- The `routes.yaml` file defines the [routing configuration];
- The `services.yaml` file configures the services of the [service container];
- The `bundles.php` file enables/disables packages in your application;
- The `preload.php` file defines the classes to [preload with OPcache];
- The `reference.php` file is autogenerated by Symfony and contains definitions that improve IDE autocompletion and static analysis when using PHP as the configuration format;
- The `config/packages/` directory stores the configuration of every package installed in your application;
- The `config/routes/` directory stores the routing configuration loaded by installed packages (e.g. `framework.yaml`).

### The Documentation Directory

The `docs/` directory contains the documentation files from Vitepress.

### The Migrations Directory

The `migrations/` directory hosts all database migrations.

### The Node Modules Directory 

The `node_modules/` directory is a folder in a Node.js project that stores all third-party libraries, packages, and their nested dependencies. This directory is ignored from Git commits.

### The Public Directory

The `public/` directory  is the only directory accessible directly from the internet. It serves as the document root for your web server (like Apache or Nginx) and acts as the public face of your application.

It contains the `index.php` file which bootstraps the framework. 

### The Source Directory

The `source/` directory contains the core code of your application. We'll explore this directory in more detail soon; however, almost all of the classes in your application will be in this directory.

### The Templates Directory

The `templates/` directory is the folder where all your HTML view files (Twig) are stored. 

### The Tests Directory

The `test/` directory contains all test.

### The Translations Directory

The `translations/` is the central folder where all your translation files are stored. It is used to build multilingual websites by separating your application's text content from the actual code.

Symfony relies on a strict naming convention for files inside the translations/ directory so it can automatically detect them. The format is:

`{domain}+{locale}+{format}`

- **Domain (Optional)**: A way to group your translations (e.g., messages, validators, security). If you don't specify one, it defaults to messages.
- **Locale**: The language code (e.g., en for English, fr for French, es for Spanish).
- **Format**: The file type. Symfony supports YAML (recommended), XLIFF, or PHP.

### The Var Directory

The `var/` directory is the folder where the application stores temporary application data, logs, and compiled system files.

### The Vendor Directory

The `vendor/` directory is the folder where Composer stores all of your project's third-party PHP dependencies and libraries.
